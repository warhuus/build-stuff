## Interface changes applied by the lead before freezing
- D1 (modularity B2). `Derive<R,T> = (raw, selection, config?: MetricsConfig) => DeriveOutput<T>`. Every derive takes an optional third parameter `config` defaulting to `METRICS_CONFIG`; `loadCard` passes the same `config` it gave the loader. Derive never imports numeric/label config values it could take from `config` (bins, BREAKDOWN_MAX_GROUPS, gate values, escalated labels, window keys). Static texts (CAVEAT_TEXT, stage labels) may be imported directly.
- D2 (modularity M1, seam). `DurationRaw.notWorked: readonly AlertLifecycleRow[] | null`. New shared loader `shared/notWorkedAlerts.ts` (Agent D) runs the 4.2 not-worked fetch (closed-and-not-open-now events in window + opened events of their items) and maps them to `AlertLifecycleRow[]` with `compute/alertLifecycle.ts` (`worked=false`, attrs from the closed event = latest pipeline event, W6). It does not exclude L2 ids; the 4.2 derive excludes alerts present in the L2("now") facts and alerts with any human event (spec §9 4.2).
- D3 (osdk F2). `EventFilter.predicates` is a non-empty tuple.
- D4 (spec SF-11). `BREAKDOWN_NOT_ALLOWED = "breakdown-not-allowed"` in config.

## Decisions
- D5 (modularity B1, cache typing). `shared/cache.ts` holds one typed map per card: `{ [C in CardId]: Map<string, CacheEntry<CardRaw[C]>> }` with `CacheEntry<R> = { output: LoaderOutput<R>; computedAt: string }` plus in-flight promises per key, so `loadCard<C>` and `useMetric` stay cast-free. Also exports `clearMetricsCache()`, a version counter + `subscribe` for `useSyncExternalStore`, and a registry that shared-loader memos register their `clear` with (so clear empties L1/L2/L3/notWorked memos). No TTL.
- D6 (modularity M4 + spec SF-01; spec §11). Raw cache key = `card | window.key | view (itemFunnel only) | otifMode (otifOutcome only) | filtersKey (every card except userFunnel) | breakdown`. `filtersKey` is dimension-qualified and canonical (sorted, de-duplicated values per dimension, e.g. `bl=a,b;pl=;rg=x;pt=`). Unit and ageingThresholdDays never in the key. One function `cacheKey(cardId, selection, breakdown)` in `selection.ts`. Assumed (record in QUESTIONS): view/otifMode only for the cards that read them. 4.5 and 4.1 keep window and filters in the key (spec §11 literal) — supersedes architect A1.
- D7 (modularity M5). Shared-loader memos (`shared/memo.ts` or inside each shared loader) own an internal `AbortController`; each caller's signal subscribes; the internal controller aborts only when every subscriber has aborted; a rejected/aborted memo entry is evicted so the next caller retries. Shared loaders never acquire the app semaphore (X3).
- D8 (modularity M2). Event classification (viewed / action / writeback / human / opened / closed / tie order) lives once in `compute/eventPredicates.ts`, taking values from `config`. `compute/alertLifecycle.ts` builds facts from it. The fake source reuses `compute/eventPredicates.ts` for its predicate semantics (the fake may import compute; it is a port implementation used by tests).
- D9 (modularity M3). `compute/breakdown.ts` provides the generic helpers reused by every card: `topGroups(counts, max)` (count desc, name asc), `buildBreakdown(...)` producing `BreakdownResult<T>` (other for additive, overlapRatio for non-additive over ALL groups before truncation, truncated {shown,total} only when top-N cut), and `groupRows(rows, keyOf)` for client-side grouping (4.2–4.6). No per-card copies.
- D10 (modularity M6). Layer placement: `window.ts`, `selection.ts`, `breakdowns.ts` are in the pure layer with compute/query (they import config and types only). The dim → apiName mapping lives only in `source/osdk`.
- D11 (row-cap, spec SF-02). Shared loaders return `{ rows, capped }`; any card using L1/L2/L3/notWorked/itemsById/verdicts propagates `capped` → `status: "partial"` + `row-cap`.
- D12 (SF-03, W4). itemFunnel alert view calls L2 with the SELECTED window; 4.3 the selected window; 4.2, 4.4, 4.6 the `"now"` window then filter `closedAt` in the selected window.
- D13 (SF-04). Placeholder-blocked result: `{ status: "blocked", blocked: { reason: "needs-integration-value", unblockedBy: INTEGRATION_UNBLOCKED_BY[key] }, caveats: ["needs-integration-value"], window, computedAt }`, no network calls. Stub cards carry their stub caveats. Order of checks in loadCard: breakdown-not-allowed → stub → placeholder → cache/load (architect A8, kept).
- D14 (osdk F1). An id lookup with zero ids returns `{ rows: [], capped: false }` without a server call (OSDK `$in: []` matches ALL objects). Fake mirrors it (and tests it).
- D15 (osdk F4). Row mapping in the OSDK adapter: a row missing its primary key / id field is dropped; other missing fields become `null`; `eventTimestamp` missing → row dropped (spec says non-null). Escalated group labels via `String(v) === "true"` (F6). `$ranges` gets a mutable copy (F5). Group-by switch at the call site so `$group` is precisely typed (F7).
- D16 (osdk F3). Agent C's recording-client tests must assert the exact where clauses sent for AlertHistory and OtifOrderVerdict never contain persona / riskType / priorityAtEvent / critClassification.
- D17 (architect A2). 3.1 with a breakdown keeps the per-bucket value calls in addition to the 14 grouped calls (bucket totals and `other` include null-dimension items). Assumed; record in QUESTIONS (spec §9 3.1 cost line).
- D18 (architect A3, A4, A5, A7, A9, A10) accepted. A9: ageingBacklog `window` = resolved selection window; `asOf` = now at load. Record A2–A5, A7 in QUESTIONS "Assumed".
- D19 (SF-05). QUESTIONS.md "Known deviations" lists Appendix A P2 a–e verbatim, plus two Excel items not offered: section-1 business-line breakdown (Excel 1.0/§1 header: depends on directory, S1) and 4.1 "alerts touched per item" segmentation (not in spec).
- D20 (SF-10). Generic fetch methods stay; X2 is enforced by review (phase 3 OSDK reviewer) and by a test that lists every loader's fetch calls against the fake.
- D21 (M7/M8). Planned splits (allowed inside existing folders): `loaders/itemFunnel.ts` + `loaders/itemFunnelItemView.ts` + `loaders/itemFunnelAlertView.ts`; `source/osdk/compileSpec.ts` + `compileWhere.ts` + `groupBy.ts`; `source/osdk/osdkSource.ts` + `osdkAggregates.ts` + `osdkFetches.ts` + `rowMapping.ts`; `source/fake/fakeSource.ts` + `fakeEval.ts`; fixtures may split `fixtures.ts` + `fixtureEvents.ts`.
- D22 (M9). The lead extends structure.test.ts with import-direction, apiName-literal, 40-line function and 150-line loader checks.
- D23. `loadCard.ts` is built by Agent F (with hooks), since both share cache/concurrency.
- D24. Progress: `onProgress({ loaded })` where `loaded` is cumulative rows across all fetches of one card load (loadCard wraps the callback and sums per fetch); `progress` on the result is the last value.
