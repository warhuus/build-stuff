## Checked, no finding

- **Return type is inferred from `cardId` with no casts.** The probe `probe_ok.ts` imports only from `src/data/metrics/index` and asserts exact type equality for all 12 cards. Examples: `useMetric("itemFunnel", sel)` gives `MetricResult<CardData<FunnelSeries>>`, `.data?.total.stages` gives `readonly FunnelStage[] | undefined`, `loadCard("ageingBacklog", …)` gives `.data?.total.threshold.pct: number | null | undefined`, and the three stubs give `readonly MovementRow[]` / `readonly CalibrationRow[]` / `readonly RolledMonthRow[]`. Apart from the three TYP-01 narrowing lines, tsc reports no errors in it.
- **Wrong usages fail to compile.** tsc output for `probe_bad.ts`:
  - `TS2551: Property 'stagez' does not exist on type 'FunnelSeries'. Did you mean 'stages'?`
  - `TS2339: Property 'bins' does not exist on type 'FunnelSeries'.`
  - `TS2339: Property 'stages' does not exist on type 'readonly BucketRow[]'.`
  - `TS2345: Argument of type '"itemFunnnel"' is not assignable to parameter of type '"userFunnel" | "itemFunnel" | …'`
  - `TS2345: Argument of type '"userRole"' is not assignable to parameter of type '"businessLine" | … | null | undefined'`
  - `TS2322: Type '60' is not assignable to type '"now" | 7 | 14 | 30 | 90'.`
  - `TS2339: Property 'push' does not exist on type 'readonly FunnelStage[]'.`
  - `TS2551: Property 'workedRatio' does not exist on type 'OutcomeHeadline'. Did you mean 'workedRate'?`
- **Casts.** Production `src/` (tests excluded) contains no `as X` cast. The only ` as ` outside `as const` is `import * as sdk` (defaultSource.ts:6). There are no non-null assertions (`!`), no `as unknown as`, no `@ts-ignore` and no `satisfies`. Type-aware eslint with `consistent-type-assertions: never` and `no-non-null-assertion` reports 0 hits.
- **`any`.** No explicit `any` anywhere, and no `// OSDK boundary:` uses. A TypeChecker walk over every non-test node found no `any`-typed expression apart from TYP-04. The other hits were checker artifacts on destructuring patterns and type-predicate parameters. Type-aware `no-unsafe-*` finds only TYP-04.
- **OSDK types do not leak out of `source/osdk`.** Nothing outside `source/osdk` imports `@osdk/*` or `@app/sdk`. `createOsdkSource` and `getDefaultOsdkSource` return the port type `MetricsSource`, and the port has no OSDK types in it. Only `MetricsSourceContext.ts` imports `source/osdk/defaultSource`.
- **Explicit return types.** `@typescript-eslint/explicit-module-boundary-types` reports 0 hits. `explicit-function-return-type` finds only one hit, the non-exported local arrow `split` at riskDistribution.ts:49, which no stated rule covers.
- **readonly.** All fields of exported interfaces in types.ts, outputTypes.ts, rowTypes.ts, rawTypes.ts, specs.ts, MetricsConfig, CardMeta, StubMeta, BreakdownRule and LoadCardOptions are `readonly`. All exported arrays are `readonly` or `as const`, and all exported config records are `Readonly<Record<…>>`. `CARDS` is `Readonly<Record<CardId, CardMeta>>`. `DEFAULT_SELECTION` is a readonly `Selection` with readonly filter arrays.
- **Public surface (§7).** The values are exactly the 13 that §7 lists, with no extras. `CARD_IMPL`, `peekCard`, `precheckCard` and `createProgressSum` are not exported. The extra types (`CardMeta`, `StubMeta`, `MetricsConfig`, `CardResult`, `LoadCardOptions`, `MetricsSourceProviderProps`, `SetSelection`, `ItemFunnelView`, `OtifMode`, `Progress`, `BlockedInfo`, `Window`) are all used by exported values. For the missing closure of `MetricsSource`, see TYP-03.
- **`CardOutput` map.** It has 12 keys, equal to `CARD_IDS`. `CardImplMap = { [C in CardId]: CardImpl<C> }` and the typed cache maps (D5) keep `loadCard<C>` cast-free. A missing key would fail to compile, because `CardOutput[C]` is indexed with `C extends CardId`.
- **Extension seams.** Renaming a `BreakdownDimension` member fails at 3 dispatch sites (phase-1 m2 is effectively covered). Extending `ClosureGroup` (S3) fails at composition.ts:24. `StageId` feeds `STAGE_LABELS: Record<StageId, string>`, so a new stage needs a label. Adding a dim is the unsafe case (TYP-05).
- **Selection typing.** `Selection.view: ItemFunnelView` (`"item" | "alert"`), `otifMode: OtifMode`, and `window: WindowKey` all come from config tuples. `normalizeSelection` validates untrusted input through `SelectionInput` (fields typed `unknown`).
- **Optional hardening (not a stated rule, not reported).** With `noUncheckedIndexedAccess`, tsc gives 25 index-access errors in production code; spot checks found all of them index-aligned or guarded. With `exactOptionalPropertyTypes`, there are 5 errors in osdkFetches.ts (`$nextPageToken: string | undefined`). These are worth a line in INTEGRATION.md if the host tsconfig enables that flag.

## Summary

No blockers.

The majors:
- **TYP-01:** `MetricResult` is optional-field soup, which breaks instructions §10. Narrowing on `status` does not narrow `data`, `blocked` or `error`. This needs a lead decision because types.ts is frozen, but the union can stay compatible with the spec shape.
- **TYP-02:** `useMetricsSelection`'s updater form silently loses updates when two calls happen in one tick (reproduced).
- **TYP-03:** `loadCard` requires a `MetricsSource`, but the public API has no way to get one, and the exported `MetricsSource` type is not self-contained.

The minors:
- **TYP-04:** implicit `any` in groupBy.ts through `Array.isArray`.
- **TYP-05:** a new `BreakdownDimension` compiles but falls into `default` branches that silently compute something else (the escalated breakdown in userFunnel).
- **TYP-06:** unstable provider props abort and restart loads (reproduced 4 → 12 calls).
- **TYP-07:** error codes are untyped.
- **TYP-08:** correlated nullable fields in `BreakdownResult` and `FunnelStageRaw`.
