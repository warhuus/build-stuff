# Phase 1 review 2: modularity and reuse

Reviewer: phase 1 reviewer 2 (report only; no source file edited).
Scope: DESIGN.md, config/metrics.ts, metricsCodes.ts, metricsText.ts, data/metrics/types.ts, outputTypes.ts, rowTypes.ts, rawTypes.ts, query/specs.ts, source/MetricsSource.ts.

Overall: the layering, the four closed set types and the 16-method port are sound. Every spec §9 plan and every Appendix A X1 capability can be written with the current specs (checked plan by plan: 1.1–1.4 incl. escalated pivot, 2.0–2.4 both views incl. term b and outside paths, 3.1 incl. grouped values, 4.1, 4.2 not-worked "closed and not open now" subtract and opened-events pivot, 4.5, 4.6, L1–L3). The raw types are unit- and threshold-independent (O3 holds). No property apiName string literal was found outside the V7 exception. The problems below are mostly in the seams between layers: the cache and derive typing, derive config, the rule-9 seam for 4.2, and shared compute helpers that the inventory does not name yet.

Evidence for B1: a tsc probe (scratchpad) typed the catalogue as `{ [C in CardId]: { load: Loader<CardRaw[C]>; derive: Derive<CardRaw[C], CardOutput[C]> } }`. With that typing, `loadCard<C>` infers `MetricResult<CardData<CardOutput[C]>>` on the fresh-load path with no cast. When a raw value is read back from a cache typed `Map<string, LoaderOutput<CardRaw[CardId]>>`, tsc fails: TS2345, `CardRaw[CardId]` (union incl. null) is not assignable to `CardRaw[C]`.

## Checks that passed
- **Port width.** No method is redundant: `countItems` vs `countRisk`, and `fetchItems` vs `fetchItemsByIds`, differ in object type or chunking. Nothing needed is missing. X1 coverage: term b = `countOpenAlerts(aof) − countOpenAlerts(ofEvents(life))`. Escalated on events = `where(ofOpenAlerts(where(all, escalated=v)), filter)`. The eventType group maps to `actionType`/`writebackType`. Not-worked = `subtract(closed, ofOpenAlerts(ofEvents(closed)))` plus `where(ofItems(ofEvents(final)), opened)`. Grouped risk = `countItemsBy(ofRisk(where(set,b)), d)`. Open alerts by filters = `ofItems(filtered(all,f))`. Items by id = `fetchItemsByIds`. The fake can implement it with the same semantics through one evaluator per set type.
- **Group-by-only rule.** It holds structurally: `EventFilter` has predicates and a window only, and `OpenAlertCondition` covers routingPersona/priority/escalated only.
- **O3.** No raw type depends on unit or threshold. 3.1 fetches counts and values together.
- **Imports.** The reviewed files import downward only: config ← types ← query ← source port.
- **apiNames.** No apiName string literal appears outside the V7 union in config/metrics.ts:58-61 (the coincidental business names are covered in m1). Link names appear only in comments.
- **File sizes.** All reviewed files are ≤ 210 lines (config/metrics.ts is the largest and has little headroom).

## Interface change requests
None raised by this reviewer as a hard stop. B1 and B2 change `shared/cache` and possibly `RawBase`/catalogue typing. They must be settled by the architect before phase 2 agents write loadCard, the cache and derives.
